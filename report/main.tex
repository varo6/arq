\chapter{Introducción}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

Este reporte documenta el desarrollo de un sistema de seguridad basado implementado en el microprocesador PicoBlaze. El objetivo principal es implementar un mecanismo de autenticación que solicita al usuario una contraseña de 4 caracteres, la procesa mediante una función de hash implementada en hardware, y verifica si coincide con una clave predefinida. Estará controlado por una maquina de estados y conectado a un monitor VGA. Finalmente, se añade una extensión por software donde se puede enviar esa contraseña a probar remotamente, desde internet.

El sistema integra varios componentes:
\begin{itemize}
    \item Una modificación de la arquitectura del PicoBlaze para incluir una instrucción personalizada de hash.
    \item Periféricos hardware para la comparación de contraseñas, visualización VGA y gestión de estados.
    \item Un programa en ensamblador que coordina toda la lógica con los registror pasado por un parser a la memoria ROM del picoblaze en VHDL.
\end{itemize}

El funcionamiento general es el siguiente: el sistema muestra un mensaje de bienvenida, el cual está incluido en la ram. Espera la introducción de 4 caracteres por parte del usuario, los procesa con la función hash, compara el resultado con la contraseña almacenada (``HOLA'' hasheada, aunque podría ser cualquiera que se decida previamente a volcar el programa en la placa), y muestra el resultado tanto por el puerto serie como por la salida VGA. En caso de error, el usuario dispone de 3 intentos antes de que el sistema entre en un estado de bloqueo temporal de 5 segundos. Todo esto controlado por la máquina de estados.

El mapa E/S elegido contempla todas las salidas y entradas de los périféricos y comunicaciones con el PicoBlaze, por lo que podemos comunicar todos los resultados de manera eficiente:

\section{Hasher}

Para implementar la función de hash se ha añadido una nueva instrucción al repertorio del PicoBlaze denominada \texttt{HASHER}. Esta instrucción recibe los mismos parámetros del flip, ya que toma un operando de 8 bits y produce un resultado de 8 bits mediante una serie de transformaciones combinacionales, pero no es lineal, la finalidad es de ofuscar al máximo posible la contraseña de forma que el picoblaze pueda actuar como una especie de \textit{caja negra}, donde no se pueda extraer la contraseña ni interpretar las operaciones de ninguna forma.

Para que el PicoBlaze lo entienda como instrucción en cualquier parte del sistema ha hecho falta modificar partes esenciales como el código fuente del parser, que recoge todas las instrucciones que el PicoBlaze debe saber. Para ello, en zonas como la lista de instrucciones, el número total o declaración de operandos de entrada y de salida, se añadió todo lo relacionado con el \texttt{HASHER}.

Es importante saber que aunque el parser compile bien (se ha tenido que generar un nuevo ejecutable tras la modificación, ya que tiene otro código fuente), o se haga el parseo de los archivos \texttt{.asm} correctamente, esto no significa que la instrucción esté programada correctamente, pero comprueba que los operandos tengan sentido, que todo tenga consistencia y que no haya fallos cuando en el ensamblador se encuentre una llamada a \texttt{HASHER}. Aunque ya esté dentro del PicoBlaze, hay que programar su funcionamiento.

\subsection{Orden y lógica de la instrucción}

\begin{figure}[H]
 	\centering
 	\includegraphics[width=0.9\textwidth]{resources/img/hasher.png}
 	\caption{Diagrama del módulo Hasher.}
 	\label{fig:hasher}
 \end{figure}


Como se muestra en la figura anterior, la arquitectura del módulo hasher se compone de 5 etapas en cascada:

\texttt{stage1\_flip:} La primera transformación invierte el orden de los bits del operando de entrada. Lo que tendríamos antes como flip. El bit 0 pasa a ser el bit 7, el bit 1 pasa a ser el bit 6, y así sucesivamente.

\begin{lstlisting}[language=VHDL, caption={Etapa FLIP}]
flip_gen: for i in 0 to 7 generate
    stage1_flip(i) <= operand(7-i);
end generate;
\end{lstlisting}

\texttt{stage2\_xor:} El resultado de la etapa anterior se combina mediante una operación XOR con una constante denominada \texttt{MAGIC\_KEY} cuyo valor es \texttt{0xA5} (10100101 en binario). La clave mágina es lo que normalmente se conoce como clave privada, aunque en este caso está pensado para dejarlo en el código sin cambiar, de forma que desde fuera no se podría revelar.

\begin{lstlisting}[language=VHDL, caption={Etapa XOR}]
constant MAGIC_KEY : std_logic_vector(7 downto 0) := x"A5";
stage2_xor <= stage1_flip xor MAGIC_KEY;
\end{lstlisting}

\texttt{stage3\_rot:} Se realiza una rotación hacia la izquierda de 3 posiciones. Los 3 bits más significativos pasan a ocupar las posiciones menos significativas.

\begin{lstlisting}[language=VHDL, caption={Etapa ROT}]
stage3_rot <= stage2_xor(4 downto 0) & stage2_xor(7 downto 5);
\end{lstlisting}

\texttt{stage4\_swap:} Se intercambian los nibbles (grupos de 4 bits) del byte. El nibble alto pasa a ser el bajo y viceversa.

\begin{lstlisting}[language=VHDL, caption={Etapa NIBBLE SWAP}]
stage4_swap <= stage3_rot(3 downto 0) & stage3_rot(7 downto 4);
\end{lstlisting}

\texttt{stage5\_mix: }La etapa final aplica una mezcla no lineal utilizando rotaciones adicionales y operaciones lógicas:

\begin{lstlisting}[language=VHDL, caption={Etapa MIX}]
r1 <= stage4_swap(6 downto 0) & stage4_swap(7);          -- rotl1
r2 <= stage4_swap(5 downto 0) & stage4_swap(7 downto 6); -- rotl2
stage5_mix <= stage4_swap xor r1 xor (stage4_swap and r2);
\end{lstlisting}

Esta etapa combina el resultado anterior con dos versiones rotadas de sí mismo (1 y 2 posiciones respectivamente), añadiendo no linealidad mediante la operación AND.

El resultado final se registra de forma síncrona en el flanco de subida del reloj, lo que añade un ciclo de latencia pero mejora el timing del diseño.

\section{Comparador Combinacional}

El módulo \texttt{modulo\_xor} implementa la comparación entre la contraseña introducida por el usuario (ya hasheada) y la contraseña correcta almacenada en el sistema.

La idea de elegir al comparador como un periférico separado es para mantener la modularidad del diseño. De esta forma, el comparador puede ser probado y verificado de forma independiente antes de integrarlo con el resto del sistema. Además, es agnóstico respecto a la fuente de datos, el algoritmo que se use en el hasher, o si la vga está activa o no, de forma que cualquier problema de funcionamiento en otras partes no interfiere con la comparación.

\subsection{Funcionamiento}


\begin{figure}[H]
 	\centering
 	\includegraphics[width=0.7\textwidth]{resources/img/moduloxor.png}
 	\caption{Diagrama del comparador combinacional.}
 	\label{fig:moduloxor}
 \end{figure}

El módulo lee 4 caracteres hasheados a través de los puertos \texttt{0xFE}, \texttt{0xFD}, \texttt{0xFC} y \texttt{0xFB}. Estos valores se almacenan en registros internos cuando el PicoBlaze realiza una escritura (señal \texttt{write\_strobe} activa).

La contraseña correcta corresponde a la palabra ``HOLA'' procesada por el hasher:

\begin{lstlisting}[language=VHDL, caption={Contraseña hasheada almacenada}]
saved_char_1 <= "00101011";  -- 'H' hasheado
saved_char_2 <= "01011010";  -- 'O' hasheado
saved_char_3 <= "01011011";  -- 'L' hasheado
saved_char_4 <= "10110010";  -- 'A' hasheado
\end{lstlisting}

\subsection{Comparación}
La comparación se realiza mediante operaciones XOR entre cada carácter recibido y su correspondiente valor almacenado:

\begin{lstlisting}[language=VHDL, caption={Operaciones XOR de comparación}]
out_xor_1 <= saved_char_1 XOR char_1;
out_xor_2 <= saved_char_2 XOR char_2;
out_xor_3 <= saved_char_3 XOR char_3;
out_xor_4 <= saved_char_4 XOR char_4;
\end{lstlisting}

Si todos los resultados XOR son cero (es decir, todos los caracteres coinciden), el módulo devuelve \texttt{0x00} indicando éxito. En caso contrario, devuelve \texttt{0xFF} indicando fallo.

\section{VGA}

La interfaz VGA se implementa mediante dos módulos: \texttt{vga}, encargado de la correcta comunicación con el monitor y \texttt{vga\_inter} que actúa como interfaz entre el controlador VGA base y el sistema PicoBlaze.

\subsection{Diseño del Hardware VGA}

La placa Spartan-3E incluye un puerto VGA mediante un conector DB15 que permite la conexión directa a monitores VGA estándar. El FPGA controla directamente las cinco señales VGA mediante resistores en serie:

\begin{itemize}
    \item \textbf{Señales de color}: VGA\_RED (H14), VGA\_GREEN (H15), VGA\_BLUE (G15) - cada una con un bit de profundidad.
    \item \textbf{Señales de sincronización}: VGA\_HSYNC (F15), VGA\_VSYNC (F14) - niveles LVTTL.
\end{itemize}

Los resistores en serie de 270$\Omega$ en combinación con la terminación de 75$\Omega$ del cable VGA aseguran que las señales de color permanezcan en el rango especificado de 0V a 0.7V. Con 3 bits (uno por color), el sistema puede generar 8 colores diferentes.

\subsection{Módulo VGA Base}

El módulo \texttt{vga} implementa el controlador de temporización VGA siguiendo el estándar VESA para resolución 640x480 a 60 Hz.

\subsubsection{Decisiones de Diseño}

\paragraph{Frecuencia de reloj pixel:} Se utiliza un reloj de 25 MHz, obtenido dividiendo el reloj del sistema (50 MHz) por 2. Esta frecuencia es el estándar para modo VGA 640x480@60Hz, calculada como:
$$\text{Pixel Clock} = 794 \times 528 \times 60 \text{ Hz} \approx 25.175 \text{ MHz}$$

\paragraph{Dimensionamiento del frame:} Se configuró la pantalla a 794$\times$528 píxeles totales en lugar de solo 640$\times$480 para incluir los intervalos de blanking necesarios:

\begin{itemize}
    \item \textbf{Blanking horizontal}: Los píxeles 640-793 no son visibles e incluyen el front porch, sync pulse y back porch.
    \item \textbf{Blanking vertical}: Las líneas 480-527 no son visibles e incluyen los intervalos verticales de sincronización.
\end{itemize}

Estos márgenes permiten que el haz de electrones (en CRT) o los controladores LCD tengan tiempo de retornar a la posición inicial antes de comenzar la siguiente línea o frame.

\subsubsection{Parámetros de Temporización}

El diseño implementa los siguientes parámetros de temporización:

\begin{itemize}
    \item \textbf{Horizontal}:
    \begin{itemize}
        \item Total: 794 píxeles por línea (0-793)
        \item Área visible: 640 píxeles (0-639)
        \item Pulso de sincronía: píxeles 649-746 (96 píxeles de ancho, nivel bajo)
        \item Inhibición de color: activa después del píxel 639
    \end{itemize}

    \item \textbf{Vertical}:
    \begin{itemize}
        \item Total: 528 líneas por frame (0-527)
        \item Área visible: 480 líneas (0-479)
        \item Pulso de sincronía: líneas 489-491 (2 líneas de ancho, nivel bajo)
        \item Inhibición de color: activa después de la línea 479
    \end{itemize}
\end{itemize}

\subsubsection{Arquitectura Interna}

El módulo \texttt{vga} utiliza dos contadores independientes:

\begin{enumerate}
    \item \textbf{Contador de píxeles}: Incrementa con cada ciclo de reloj de 25 MHz, cuenta de 0 a 793, resetea y genera pulso de incremento para el contador de líneas.

    \item \textbf{Contador de líneas}: Incrementa al finalizar cada línea (cuando el contador de píxeles alcanza el valor 746), cuenta de 0 a 527.
\end{enumerate}

Las señales de sincronización se generan mediante comparadores que detectan las ventanas temporales correspondientes. La señal de inhibición de color se activa (OR lógico) cuando el contador de píxeles supera 639 O el contador de líneas supera 479, bloqueando la salida de color durante los períodos de blanking.

\subsection{Módulo VGA Inter}

El módulo \texttt{vga\_inter} actúa como interfaz entre el controlador VGA base y el sistema PicoBlaze, implementando la lógica de visualización específica de la aplicación.

\subsubsection{Funcionalidad}

\begin{enumerate}
    \item \textbf{Generación de reloj de 25 MHz}: Divide por 2 el reloj de entrada (50 MHz) mediante un flip-flop toggle para proporcionar el pixel clock al módulo VGA base.

    \item \textbf{Captura de estado del sistema}: Lee el estado actual desde el puerto \texttt{0xDD} del bus PicoBlaze cuando se activa \texttt{read\_strobe}, almacenándolo en un registro interno.

    \item \textbf{Generación de color}: Selecciona el color RGB de 3 bits basándose en el estado actual del sistema y la posición del píxel, respetando la señal de inhibición.
\end{enumerate}

\subsubsection{Codificación de Colores}

La aplicación utiliza tres colores para retroalimentación visual al usuario:

\begin{itemize}
    \item \textbf{ROJO} (\texttt{100}): Estado de bloqueo con error (\texttt{0x81}) - indica contraseña incorrecta.
    \item \textbf{VERDE} (\texttt{010}): Estado de bloqueo acertado (\texttt{0x82}) - indica contraseña correcta.
    \item \textbf{BLANCO} (\texttt{111}): Todos los demás estados - indica sistema en espera de entrada.
\end{itemize}

Esta codificación de 1 bit por canal de color es una limitación del hardware de la placa Spartan-3E, que solo proporciona control on/off para cada canal RGB, permitiendo 8 colores totales.


%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\section{Máquina de Estados}

\subsection{Propósito y Diagnóstico Físico de la FSM}

La FSM (implementada en \texttt{modulo\_estados.vhd}) es el componente de control de nivel superior. Su función es gestionar el ciclo de vida de la seguridad, decidiendo cuándo el sistema es accesible y cuándo debe bloquearse para protegerse contra ataques de fuerza bruta.

La comprobación de su funcionamiento se realiza visualmente mediante el LED 6, el cual está conectado al bit de bloqueo de la FSM (\texttt{LED(6) <= mis\_estados(7);}).

    \begin{itemize}
        \item \textit{Encendido}: El sistema está bloqueado por la FSM (penalización de 5 segundos tras 3 fallos o estado inicial de seguridad).
        \item \textit{Apagado}: El sistema está en \texttt{estado\_escucha}, listo para recibir la contraseña.
    \end{itemize}

\subsection{Estados Definidos y Salidas Visuales}

El sistema transita por 6 estados principales que condicionan el comportamiento del software y el color de la salida VGA:

\begin{itemize}
    \item \textbf{estado\_bloqueo} (\texttt{0x81}): Estado de penalización activado al iniciar o tras el tercer fallo. El bit 7 está activo, el LED 7 se enciende y la pantalla VGA se vuelve Roja (código \texttt{100}).

    \item \textbf{estado\_escucha} (\texttt{0x01}): Reposo operativo donde el sistema está libre. El LED 7 se apaga y la pantalla VGA es Blanca (código \texttt{111}).

    \item \textbf{estado\_error1} (\texttt{0x02}) y \textbf{estado\_error2} (\texttt{0x04}): Estados de advertencia tras intentos fallidos. Permiten más intentos, pero la FSM mantiene el registro de errores previos.

    \item \textbf{estado\_error3}: Punto crítico tras el tercer fallo que provoca la transición automática a \texttt{estado\_bloqueo} por 5 segundos.

    \item \textbf{estado\_bien} (\texttt{0x82}): Autenticación exitosa. La pantalla VGA se pone Verde (código \texttt{010}) y el sistema se asegura.
\end{itemize}

\subsection{Validación Técnica: Codificación por Bits}

Los valores de los estados en la señal \texttt{out\_result} (puerto \texttt{0xDD}) responden a una lógica de codificación por bits para optimizar la identificación mediante operaciones de máscara:

\begin{itemize}
    \item \texttt{0x01} (Binario \texttt{00000001}): \texttt{estado\_escucha}. Bit 0 activo.
    \item \texttt{0x02} (Binario \texttt{00000010}): \texttt{estado\_error1}. Bit 1 activo.
    \item \texttt{0x04} (Binario \texttt{00000100}): \texttt{estado\_error2}. Bit 2 activo.
    \item \texttt{0x81} (Binario \texttt{10000001}): \texttt{estado\_bloqueo}. El bit 7 está activo. En el código ASM se utiliza la instrucción \texttt{AND s0, 80} (\texttt{80} hex = \texttt{10000000} binario) para consultar exclusivamente este bit.
    \item \texttt{0x82} (Binario \texttt{10000010}): \texttt{estado\_bien}. Indica éxito combinando el bit 1 (acierto) con el bit 7 (fin de proceso).
\end{itemize}

\subsection{Arquitectura de la máquina en VHDL}

La FSM utiliza una arquitectura de doble proceso en VHDL:

\begin{itemize}
    \item \textbf{Proceso Síncrono}: Gestiona los cambios de estado con el reloj (\texttt{clk}) y controla el temporizador de 250 millones de ciclos para la penalización de 5 segundos.

    \item \textbf{Proceso Combinacional}: Determina el siguiente estado evaluando el \texttt{port\_id} (\texttt{0xDD}) y el \texttt{write\_strobe}. Si el PicoBlaze escribe \texttt{0x00} (acierto) o \texttt{0xFF} (fallo), la FSM transita.
\end{itemize}

\subsection{Lógica de Máscara de Bits: Interconexión ASM vs. FSM}

La diferencia entre los valores reportados por la FSM y la máscara utilizada en el código ensamblador es una técnica de diseño robusta para aislar el estado de bloqueo del resto de las funciones del sistema:

\begin{itemize}
    \item \textbf{Lógica de la FSM (Valor real)}: El periférico entrega estados completos a través del puerto \texttt{0xDD}, como \texttt{0x81} (bloqueo) o \texttt{0x82} (éxito). En ambos casos, el Bit 7 está a '1', lo que indica que el sistema se encuentra en un ``estado final'' o restrictivo que requiere la atención inmediata del hardware.

    \item \textbf{Lógica del ASM (Máscara)}: El software utiliza la máscara \texttt{80} hex (\texttt{10000000} en binario) para filtrar la entrada del puerto. Su función es ignorar todos los bits secundarios (que indican sub-estados como \texttt{error1} o \texttt{error2}) y centrarse exclusivamente en el estado del Bit 7.

    \item \textbf{Operación AND s0, 80}: Al aplicar esta máscara sobre el valor de la FSM, si el resultado es distinto de cero (NZ), el programa confirma que el Bit 7 está activo y ejecuta el bloqueo del flujo principal mediante la instrucción \texttt{JUMP NZ, start}.

    \item \textbf{El Bit 7 como ``Master Lock''}: Este bit funciona como un interruptor maestro de seguridad. Mientras sea '1', el software se detiene por completo en un bucle de espera. Solo cuando la FSM libera el bloqueo (volviendo al estado de escucha \texttt{0x01}), el resultado de la operación AND es cero, permitiendo que el programa continúe con la ejecución normal.
\end{itemize}

Por lo que la estructura de la maquina de estados finita queda como:

 \end{figure}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\chapter{Assembly}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

El programa de ensamblador controla la lógica y órdenes que vaya a dar el PicoBlaze sobre el sistema, gestionando la comunicación serie, la interacción con los periféricos hardware y la presentación de resultados al usuario.

En ningún caso puede superar las 256 líneas de instrucciones, ya que usaremos un parseador para usarlo como una memoria del PicoBlaze, que va a determinar su funcionamiento. Por eso, el programa en ensamblador está limitado a la arquitectura 8 bits del PicoBlaze, como no poder enlazar muchas subrutinas o trabajar en menos de 256 instrucciones. Siendo varias las limitaciones, que trae, también es conveniente usarlo de esta forma, ya que se convierte en el ``orquestador'' de todos los périfericos: Recibe de este puerto, envia al otro, si un periférico envia cierto valor comunícalo con este puerto... Todo lo que haga pasará por el PicoBlaze.

El programa se divide en varias secciones:

\subsection{Lógica de bloqueo}
El programa comienza verificando si el sistema está en estado de bloqueo consultando el puerto de la FSM. Si el bit 7 está activo, el programa espera en un bucle constante hasta que el bloqueo termine.

\begin{lstlisting}[caption={Rutina start}]
start:
    INPUT   s0, fsm_port
    AND     s0, 80
    JUMP    NZ, start
    LOAD    S7,00
\end{lstlisting}

Tras esto, se activan las interrupciones y seguirá coprobando en un bucle de espera si debemos avanzar

\begin{lstlisting}[caption={Bucle espera}]
parte2:
    ENABLE INTERRUPT        ; Activamos interrupcion para poder escribir
bucle_espera:
    ; Comprobamos constantemente si el hardware nos bloquea de repente
    INPUT   s0, fsm_port
    AND     s0, 80
    JUMP    NZ, start       ; Si nos bloquean, saltamos al inicio (desactiva int)

    JUMP    bucle_espera    ; Si no, seguimos esperando
\end{lstlisting}

Una vez libre, el programa:
\begin{enumerate}
    \item Imprime un mensaje de bienvenida almacenado en RAM.
    \item Habilita las interrupciones.
    \item Entra en un bucle de espera, verificando continuamente el estado de bloqueo o la próxima interrupción.
\end{enumerate}

El estado de bloqueo no siempre ocurre al inicio, por lo que también se debe controlar en otras partes. Es el caso de la rutina de interrupción, ya que sabemos que \textbf{todo lo que escribimos} salta en el programa a la interrupción, incluso en otros bucles si no la tienen desactivada, por eso es importante dentro de la interrupción comprobar que el estado sigue o no siendo bloqueado. Las primeras lineas de \texttt{interrup} tienen líneas similares a las de rutina start, donde compara el bloqueo, y si lo es, llamamos a \texttt{salir\_interrup} donde se creará otro bucle de bloqueo

\begin{lstlisting}[caption={Bloquear interrupciones}]
salir_interrup:
    DISABLE INTERRUPT
    INPUT   s0, fsm_port
    AND     s0, 80
    JUMP    NZ, salir_interrup
    RETURNI     ENABLE

    ADDRESS     FF
    JUMP        interrup
\end{lstlisting}

\subsection{Rutina de interrupción}

Cuando el usuario envía un carácter por el puerto serie, se dispara la interrupción. Lo primero que hará será comprobar el estado de bloqueo, donde la FSM debe haber dejado algun valor válido que confirme que no esté bloqueado, y si es así, pasa a la lógica de la interrupción. Para empezar, se va a escuchar las cuatro letras necesarias para comparar la contraseña, pero como sabemos que está hasheada dentro del periférico, antes de enviarla al puerto correspondiente de cada char, se pasa por una rutina hashea. La rutina hashea hace lo siguiente:


\newpage

\begin{lstlisting}[caption={Rutina hashea}]
hashea:
    CALL    recibe
    LOAD    txreg, rxreg
    CALL    transmite
    HASHER  rxreg
    RETURN
\end{lstlisting}


Lo primero que hará será imprimir por pantalla el caracter que se recibe, ya que de forma contraria, el usuario no tendría forma de comprobar si se está enviando su input. Después, llama a la instrucción \texttt{HASHER} que previamente se ha implementado para modificar la char y vuelve a donde se llamó. Contiene las instrucciones necesarias para un bucle entero de recibo letra, envío, y hasheo, por lo que se llamará 4 veces y se añadirá cada vez al puerto correspondiente:

\begin{lstlisting}[caption={Hashea chars y envia al puerto}]
CALL        hashea
OUTPUT      rxreg, FE

CALL        hashea
OUTPUT      rxreg, FD

CALL        hashea
OUTPUT      rxreg, FC

CALL        hashea
OUTPUT      rxreg, FB

call        wait_05bit
\end{lstlisting}

Tras los valores hasheados introducidos en sus puertos correspondientes, se espera que el periférico encargado de comparar las letras haya hecho su trabajo y haya guardado el valor correspondiente en el puerto \texttt{0xFA}, por lo que se lee el valor que existe:

\begin{lstlisting}[caption={Recibir resultado XOR}]
INPUT       rxreg, FA
\end{lstlisting}

Y el resultado, sea bien o mal, se envía a los periféricos que trabajarán con este valor: la máquina de estados y el vga

\begin{lstlisting}[caption={Comunicación de resultados a FSM y VGA}]
OUTPUT      rxreg, DD  ;puerto fsm
OUTPUT      rxreg, EF  ;puerto vga
\end{lstlisting}

Aunque la máquina de estados esté contando los errores, también se hace una pequeña comparación sobre el valor que viene del periférico que compara y según si es el correcto o no, se llama a \texttt{rutinabien} o \texttt{rutinamal}, que imprimirán un mensaje de felicitación o de que no es correcta la palabra. Ambas harán uso de otra rutina creada llamada \texttt{saltolinea}, donde enviará por el puerto serie los valores que hyperterminal interpreta como el salto de línea.

\begin{lstlisting}[caption={Rutinas saltolinea y rurinamal}]
saltolinea:
    LOAD    txreg,0D        ; CR
    CALL    transmite
    LOAD    txreg,0A        ; LF
    CALL    transmite
    RETURN

rutinamal:
    CALL    saltolinea
    LOAD    txreg,4D        ; 'm'
    CALL    transmite
    LOAD    txreg,41        ; 'a'
    CALL    transmite
    LOAD    txreg,4C        ; 'l'
    CALL    transmite
    CALL    saltolinea
    CALL    transmite

    JUMP    fin
\end{lstlisting}

\subsection{El ``beep''}
La \texttt{rutinabien}, además de imprimir un \texttt{FELICIDADES!!} de forma similar a la de rutinamal, enviará un sonido al puerto serie. Esta funcionalidad adicional se ha hecho buscando qué valor podría hyperterminal detectar como un sonido, y se econtró que el hexadecimal \texttt{07} se puede usar para que hyperterminal le mande un sonido de aviso al Windows que lo esté ejecutando. Por lo que el inicio de rutinabien, si se ha acertado la palabra, emite el sonido:


\begin{lstlisting}[caption={Emitir sonido mediante ASM}]
rutinabien:
   LOAD    txreg, 07       ; Valor del beep
   CALL    transmite
   ...
   (resto de rutinabien)
   ...
\end{lstlisting}

\subsection{Comunicación serie}

Las rutinas \texttt{recibe} y \texttt{transmite} implementan comunicación serie por software (bit-banging) a 9600 baudios. Utilizan temporizaciones mediante las rutinas \texttt{wait\_1bit} y \texttt{wait\_05bit}. Están hechas por los profesores en las prácticas de clase y hemos decidido no tocarlas.

\chapter{Conclusiones}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

El desarrollo de este proyecto ha permitido explorar la integración de componentes hardware y software en un sistema embebido basado en PicoBlaze. Las principales conclusiones son:

\begin{enumerate}

    \item \textbf{Diseño modular}: La separación en módulos independientes (hasher, comparador, VGA, FSM) facilita el desarrollo, prueba y mantenimiento del sistema. Cada componente puede verificarse de forma aislada antes de la integración.

    \item \textbf{Interacción hardware-software}: El proyecto ilustra cómo el software (programa en ensamblador, aplicaciones externas como RS-232 o el picowifi) y el hardware (periféricos VHDL) cooperan para implementar funcionalidad compleja. El PicoBlaze actúa como coordinador mientras los periféricos realizan tareas especializadas.

    \item \textbf{Seguridad por diseño}: Aunque se trata de un sistema didáctico, incorpora principios básicos de seguridad como el hash de contraseñas, límite de intentos y tiempo de bloqueo. Esto demuestra cómo implementar mecanismos de seguridad a nivel hardware.

    \item \textbf{Retroalimentación visual}: La integración de la salida VGA proporciona una interfaz visual inmediata del estado del sistema, complementando la comunicación serie tradicional.
\end{enumerate}
